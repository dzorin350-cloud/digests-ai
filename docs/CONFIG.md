# Конфиг дайджеста: `digests/<id>.yaml`

Один файл — один дайджест. Имя файла — его `id` (`digest collect morning` ищет `digests/morning.yaml`).
Полные примеры: `digestkit/templates/` (`digest templates`).

```yaml
title: Утренний дайджест          # заголовок выпусков и писем
language: ru                       # язык текста (ru / en / …)
timezone: Europe/Moscow            # для дат и расписания контуров
reader: >-                          # кто читает и зачем — главный ориентир тона и отбора
  Частный инвестор в облигации …
style: Коротко, с цифрами.          # пожелания к тексту
remind_after_days: null            # напомнить один раз о важном сюжете через N дней (null — никогда)

cadences:
  daily:   {enabled: true, max_age_hours: 36}   # что опубликовано раньше — уже не новость
  weekly:  {enabled: true, weekday: 6}          # 0 = пн … 6 = вс
  monthly: {enabled: true, day: 1}

delivery:
  file: true                       # out/<id>/<дата>-<контур>.md — всегда
  email: [me@example.com]          # нужен SMTP_* в .env
  telegram_chat_id: "123456789"    # нужен TELEGRAM_BOT_TOKEN в .env
  send_empty: true                 # присылать и день без новостей («ничего нового» — тоже информация)

recipients:                        # необязательно: кому какие части (память и сбор общие)
  - {name: boss, email: boss@corp.ru, blocks: [macro], cadences: [weekly, monthly]}
  - {name: analyst, telegram_chat_id: "42", blocks: [bonds, macro]}   # cadences по умолчанию — все

news_search: {provider: google, hl: ru, gl: RU}   # для источников kind: news_search (google | bing)

blocks:
  - id: bonds                      # латиница, уникально
    title: Мои облигации
    ref: B                         # буква для ссылок в выпуске: B1, B2… (по умолчанию — первая буква id)
    brief: >-                      # что важно и что НЕ нужно — как задание живому референту
      Рейтинги, оферты, купоны, дефолты по эмитентам из списка. Повтор известного события — не новость.
    include: [рейтинг, оферта]     # подсказки: поднимают кандидата выше, но не фильтруют
    exclude: [гороскоп]            # материалы с этими словами отбрасываются кодом, до агента
    require_watch_match: true      # только материалы, где упомянут кто-то из watchlist
    max_items: 6                   # жёсткий потолок в ежедневном выпуске (меньше — нормально)
    show_quiet_watch: true         # строка по каждой позиции watchlist, даже без новостей: «Брусника — новостей нет»
    expert_comments: true          # мнения аналитиков/экспертов из источников — отдельной строкой и с именем
    color: "#059669"               # цвет карточки в письме (по умолчанию — палитра по порядку блоков)
    watchlist:
      - name: Полипласт
        aliases: [Polyplast]       # другие написания; окончания учитываются («Полипласта»)
        query: "Полипласт облигации OR рейтинг"   # запрос для news_search с "{watch}"
        note: держу П02-БО-01       # пояснение для агента
      - РЖД                        # можно просто строкой
    sources:
      - {kind: news_search, query: "{watch}"}       # поиск новостей по каждому элементу watchlist
      - {kind: rss, url: "https://site.ru", feed_url: "https://site.ru/rss", trust: 0.8}
      - {kind: telegram, url: "https://t.me/s/channel"}
      - {kind: html, url: "https://site.ru/news/", selectors: {link_pattern: "^https://site\\.ru/news/\\d+"}}
      - {url: "https://site.ru/press/"}              # kind: auto — найдёт RSS или ссылки на статьи сам
```

## Поля источника

| поле | |
|---|---|
| `kind` | `auto` (по умолчанию), `rss`, `html`, `telegram`, `news_search`, `json`, `command` |
| `url` / `feed_url` | страница и (для RSS) лента |
| `query` | для `news_search`; `{watch}` разворачивается в запрос по каждому элементу watchlist |
| `command` | для `command`: shell-команда, печатающая материалы в JSON (см. ниже) |
| `name`, `trust` | имя в выпуске; доверие 0..1 (порядок кандидатов и выбор основного источника) |
| `selectors` | для `html`: `link_pattern` (regex по ссылкам на статьи), `list` (CSS ссылок), `body` (CSS текста) |
| `fulltext` | скачивать страницу статьи, если лента даёт только анонс (по умолчанию `true`) |
| `max_items` | сколько свежих материалов брать за проход |
| `enabled` | `false` — выключить, не удаляя |

## Любые другие источники

Формат материала один: `url`, `title`, `text`, `published_at` (ISO), `source` (имя издания), необязательно
`watch` (список имён из watchlist). Принимается JSON-массив, `{"items": [...]}` (в т.ч. JSON Feed) или JSON lines.

- `kind: json` + `url`: JSON-лента или API, отдающие такой формат.
- `kind: command` + `command: "python scripts/my_source.py"`: любой скрипт (API биржи, внутренняя база,
  Reddit, корпоративный портал). Команда запускается из вашего конфига; не подключайте чужие YAML не читая.
- `digest add-items <id> --block <b> --file found.jsonl --source web-search`: материалы, которые агент нашёл
  сам (веб-поиск, MCP: Slack, почта, Notion…). Они проходят те же фильтры и ту же память и попадают в
  ближайший `digest collect`.

Источники, найденные позже (`digest sources add`), хранятся в базе со статусом `trial` и в YAML не пишутся;
`digest sources list` показывает все. Система сама отключает сломанные (`broken`, повторная попытка раз в 3 дня)
и бесполезные (`muted`: за 4 недели ≥ 15 материалов и ни один не попал в выпуск, или много 👎).
Включить обратно: `digest sources enable <id> <source_id>`.

## Письмо

Письмо — HTML с карточкой на каждый блок (инлайновый CSS, читается в Gmail, Outlook, на телефоне) плюс
текстовая версия. Тему пишет агент: хук из 1–2 главных фактов дня. Если агент тему не дал, в неё попадают
главные заголовки. Ответ на письмо привязывается к выпуску через заголовки письма и метку `[digest:<id> #N]`
внизу. В теме метки нет. Готовый HTML лежит рядом с Markdown: `out/<id>/<дата>-daily.html`. Для отправки
своим коннектором: `digest issue <id> --format json` (`subject`, `html`, `markdown`).

## Как устроена новизна

1. **Код** до всякой модели: отбрасывает материалы старше `max_age_hours`, перепечатки уже известных сюжетов
   (тот же текст или заголовок, хоть с другого сайта), `exclude`, нерелевантное для `require_watch_match`.
2. **Агент** получает кандидатов вместе с памятью: похожие известные сюжеты, их факты и даты, что читатель
   уже видел за 2 недели, его оценки и заметки. Решает: `new`, `update` (есть новый факт), `repeat`, `stale`
   (событие старое, хоть статья свежая), `irrelevant`.
3. Всё, что агент увидел, запоминается — в том числе отброшенное. Повторно оно не предлагается.
4. Сюжеты связываются в цепочки (`thread`) — по ним строятся недельный и месячный разборы.

## Хранение

Один файл `state/digest.db` (или `DIGEST_DB`) на все дайджесты. Сюжеты и выпуски хранятся всегда. Тексты статей
старше 120 дней обнуляются (URL остаются для отсева дублей), служебный мусор старше 60 дней удаляется. Год
ежедневной работы с десятком источников укладывается в сотню-другую мегабайт. Ежедневный пакет при годовой
истории собирается за пару секунд.
