# ai-digests

Личные дайджесты новостей с памятью — на любые темы. Каждое утро — только то, что действительно ново;
раз в неделю и раз в месяц — разбор того, как развивались сюжеты. Работает внутри ИИ-агента
(Claude Code, Claude Cowork, Codex, Kimi Code и др.) без ключей API, или сам по себе с любым
OpenAI-совместимым ключом.

**Главное правило: пустой блок лучше пересказа вчерашнего.** Если рейтинг эмитента понизили 10 дней назад,
вы узнаете об этом один раз — а дальше только если появится новый факт (оферта, дефолт, повышение обратно).

```
источники → сбор и фильтр кодом (дата, перепечатки, стоп-слова, watchlist)
          → кандидаты + память (что уже было, факты, даты, ваши оценки)
          → агент решает: новое / обновление / повтор / старое / мимо
          → выпуск (файл, почта, Telegram) → ваши 👍/👎 и комментарии → память и настройки
```

## Быстрый старт с агентом

```bash
git clone https://github.com/dzorin350-cloud/ai-digests.git && cd ai-digests
uv venv && uv pip install -e .          # или: python -m venv .venv && .venv/bin/pip install -e .
```

Дальше просто скажите агенту в этой папке:

> Хочу ежедневный дайджест: экономика России и мира, новости по моим облигациям (Полипласт, РЖД, ОФЗ),
> и что нового в ИИ-агентах. Присылай на почту в 8 утра.

Агент прочтёт `AGENTS.md` (Claude — ещё и скиллы в `.claude/skills/`), создаст `digests/<id>.yaml`, подберёт
и проверит источники, сделает первый выпуск и поставит расписание. Готовый пример такого дайджеста —
шаблон `morning` (`digest init my --template morning`). Ваши конфиги лежат в `digests/` и в git не попадают.

| Агент | Как запускать по расписанию |
|---|---|
| **Claude Cowork** | Запланированная задача в папке репозитория: «Запусти дайджест morning по `digest prompt run`». Почту можно отправлять и читать ответы через коннектор Gmail. |
| **Claude Code** | `/schedule` или cron: `claude -p "Запусти дайджест morning по digest prompt run"` |
| **Codex, Kimi Code, Gemini CLI, OpenCode** | их планировщик или cron с тем же текстом; инструкции — в `AGENTS.md` |
| **Без агента** | `digest run morning` из cron, в `.env` — `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |

## Вручную: шаги одного дня

```bash
digest init my --template morning      # или blank / infosec; список — digest templates
digest sources check my                # какие источники отвечают
digest collect my                      # сбор + пакет кандидатов с памятью → state/packs/my/…json
#   агент читает `digest prompt daily` и пакет, пишет решения в JSON
digest publish my --decisions decisions.json   # память + выпуск out/my/<дата>-daily.md + доставка
digest due my                          # что пора: daily / weekly / monthly
digest review my weekly                # пакет для разбора; агент пишет Markdown по `digest prompt review`
digest publish-review my --pack 12 --file review.md
digest feedback my "E1 +, B2 −, меньше про котировки"
digest status my                       # выпуски, память, оценки, что система поменяла сама
```

Все команды: `digest -h`. Инструкции для агентов: `digest prompt run | daily | review | new | tune`.

## Три контура

| | Что | Откуда |
|---|---|---|
| **Ежедневный** | Только новое за `max_age_hours` (по умолчанию 36 ч), 1–2 строки на пункт, блоки без новостей так и пишут «новостей нет». | свежий сбор |
| **Недельный** | Как развивались сюжеты за неделю: цепочки «событие → обновления», что ждать. Плюс что система поменяла в источниках. | память |
| **Месячный** | То же за месяц + тренды поверх недельных разборов: что оказалось важным, что заглохло. | память + недельные |

## Память

Всё хранится в одном файле SQLite: `state/digest.db`. Он создаётся сам при первом запуске; Postgres
и Docker не нужны. Векторы для поиска похожих сюжетов лежат там же. Для дайджеста (тысячи сюжетов)
перебор в numpy быстрее любого индекса. По умолчанию векторы считаются без модели: хэш основ слов,
с учётом русских окончаний. Для длинных горизонтов (месячные цепочки) можно подключить любой
OpenAI-совместимый `/embeddings` (`EMBED_*` в `.env`). Векторы закешируются в той же базе.

**Память должна переживать запуски.** Локально (Cowork на вашем компьютере, Claude Code, cron) так и есть.
Если каждый запуск — чистая копия репозитория (облачный агент, запланированная задача в облаке, CI),
память и ваши конфиги хранятся снимком в **приватном** git-репозитории:

```bash
# .env (или переменные окружения облачной среды)
DIGEST_STATE_GIT=git@github.com:you/my-digest-state.git   # приватный репозиторий, можно пустой
DIGEST_STATE_PASSPHRASE=…                                  # необязательно: шифрует снимок (AES-256, openssl)
```

Запуск тогда начинается с `digest state pull` и заканчивается `digest state push`. Так написано в
`digest prompt run`, агент делает это сам. Снимок — это база и папка `digests/`, ветка `digest-state`.
Если переменная задана, а `pull` не выполнялся, `digest collect` откажется работать: иначе все новости
снова оказались бы «новыми». Перенос вручную: `digest state export` / `digest state import --file …`.

## Обратная связь и подстройка

- В каждом выпуске у пункта есть метка: `[E1]`, `[B2]`… В письме рядом ссылки 👍/👎: они открывают ответ
  с готовым текстом. Можно ответить своими словами: «E1 +, B2 − уже знал, больше про бюджет».
- Ответы забираются по IMAP или из Telegram-бота (`digest feedback my --pull`), агент в Cowork может читать
  их через Gmail. Есть и прямая команда `digest feedback`.
- Оценки и заметки попадают в каждый следующий пакет: агент видит, что вам нравилось и что нет. Раз в неделю
  агент по `digest prompt tune` переносит устойчивые пожелания в `brief`, `exclude` и `watchlist` и пишет,
  что поменял, в `digests/<id>.changelog.md`.
- Источники обслуживаются сами, администратор не нужен. Новые начинают как `trial` и остаются, если
  пригодились. Сломанные отключаются и перепроверяются, бесполезные приглушаются. Обо всём этом одна строка
  в недельном разборе.

## Конфиг

Один YAML на дайджест: блоки с `brief` (что важно и что не нужно), `watchlist` (бумаги, компании, продукты),
источники (RSS, страницы сайтов, Telegram-каналы, поиск новостей Google/Bing). Подробно — [docs/CONFIG.md](docs/CONFIG.md).

Шаблоны: `morning` (экономика + облигации + ИИ-агенты), `infosec` (дайджест ИБ: 50 источников, атаки
и уязвимости, ИБ для руководства), `blank`.

**Под любую задачу.** Кроме RSS, сайтов, Telegram и поиска новостей источником может быть JSON-API, любой ваш
скрипт (`kind: command`) или находки самого агента: веб-поиск, Slack, почта через MCP (`digest add-items`).
**Получатели:** один дайджест на нескольких людей, например «руководителю — недельный и месячный по блоку
«Экономика» на почту, аналитику — ежедневный по облигациям в Telegram» (`recipients` в конфиге). Память
и сбор общие, у каждого свой выпуск.
